Del dibujo entidad–relación a las Entities

Usaremos Cine → Proyección como ejemplo común. El diagrama queda a la vista mientras descubrimos la traducción. Avanza con «Siguiente»: el SQL y el código aparecen letra a letra, en diez pasos. El botón nunca avanza por su cuenta.

Convención de nombres: tablas en singular y MAYÚSCULAS: CINE, PROYECCION, CATEGORIA. Columnas: ID, NOMBRE, PELICULA, ID_CINE o ID_CATEGORIA. PostgreSQL convierte identificadores sin comillas a minúsculas; por eso el SQL usa comillas dobles para conservar estas mayúsculas. En TypeScript mantenemos nombres camelCase.

Antes de empezar · genera la estructura desde la raíz typeorm-base

1 · Abre Git Bash en la raíz. Ejecuta pwd; la ruta debe terminar en /typeorm-base. Después genera los módulos, servicios y controladores con Nest CLI:

cd backend
npx --no-install nest g module proyeccion
npx --no-install nest g service proyeccion --no-spec
npx --no-install nest g controller proyeccion --no-spec
mkdir -p src/cine/entities src/proyeccion/entities
touch src/cine/entities/cine.entity.ts src/proyeccion/entities/proyeccion.entity.ts

nest g significa «Nest genera»: crea el módulo y añade en él el Service y el Controller. --no-spec evita archivos de pruebas que no usaremos en este recorrido. mkdir -p crea las carpetas de Entities y touch crea los dos archivos vacíos.

Ejecuta esta generación una sola vez en una copia nueva. No vuelvas a generar los archivos si ya existen. app.module.ts y frontend/App.tsx ya vienen en la base. Comprueba el resultado con find src -maxdepth 4 -print desde backend.

El módulo organiza una parte de la aplicación. El Service implementa el caso de uso y utiliza el Repository de TypeORM. El Controller publica sus rutas. Las Entities las escribiremos en entities/.

¿Qué significa @? Es un decorador: una indicación que se coloca sobre una clase, propiedad o método para que TypeORM o Nest sepan cómo utilizarlo. Piensa en él como una etiqueta con una función concreta; cada etiqueta se recuerda por el lugar donde aparece.

Regla lógica · ER 1:N

PK identifica una fila. FK guarda el ID del principal en la tabla dependiente. La FK vive en el lado N.

Entities listas · continúa con Repository, Service y Controller

Avanza por las pestañas en orden. El Repository de TypeORM se registra en el módulo y se inyecta en el Service; en este caso no hace falta crear una clase Repository aparte.

ARRANQUE · @Module

TypeOrmModule.forFeature([Cine, Proyeccion])

Registra los Repositories disponibles para el módulo.
Nest resuelve los constructores e inyecta las dependencias ↓

→

Ayuda para recordar: @Injectable() = «Nest, puedes crear y gestionar esta clase». @InjectRepository(Proyeccion) = «Nest, entrega a este constructor el Repository registrado para Proyeccion».

ARCHIVO COMPLETO · backend/src/proyeccion/proyeccion.module.ts

Qué ocurre: @Module agrupa imports, controllers y providers. forFeature registra los repositorios de las Entities en este módulo. Nest CLI conecta ProyeccionModule con AppModule.

Para recordar: imports = lo que el módulo necesita; controllers = rutas; providers = Services.

ARCHIVO COMPLETO · backend/src/proyeccion/proyeccion.service.ts

Para recordar: @Injectable permite que Nest gestione el Service; @InjectRepository(Proyeccion) pide a Nest el Repository correspondiente.

Consulta equivalente: SELECT proyeccion + cine FROM PROYECCION INNER JOIN CINE ORDER BY PROYECCION.ID ASC. El alias de QueryBuilder funciona como el alias que escribimos en SQL.

ARCHIVO COMPLETO · backend/src/proyeccion/proyeccion.controller.ts

Para recordar: @Controller fija el prefijo de la ruta; @Get responde al método HTTP GET.

Ruta resultante: GET http://localhost:3000/proyecciones. El Controller recibe la petición y delega la consulta al Service.

GIT BASH · prueba de la ruta
curl -i http://localhost:3000/proyecciones

Comprueba: el estado HTTP es correcto y el cuerpo es JSON. Si todavía no hay filas, verás []; después de insertar datos, aparecerán las proyecciones relacionadas con su cine.

Al final: @ManyToOne se coloca en la Entity del lado N y representa la relación propietaria. @JoinColumn indica la columna física de la FK. @OneToMany permite navegar desde el lado 1 a su colección y no crea otra FK. Con synchronize: false, TypeORM describe el esquema; no crea ni modifica las tablas.

La cuenta de base de datos y las instrucciones de conexión están en la guía de preparación. Las fichas y casos individuales se entregan en el espacio de aula correspondiente.
