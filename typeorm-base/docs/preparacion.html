typeorm-base · Guía de preparación

Antes de clase · Git Bash · Windows

Deja el proyecto listo antes de desconectar Internet

Sigue las pestañas en orden. Dejaremos tres piezas comunicadas: PostgreSQL guarda los datos, NestJS permite consultarlos y Expo muestra la pantalla. Git Bash es la terminal donde escribiremos comandos. Descargaremos las herramientas antes de trabajar sin Internet.

Siguiente: entra en tu espacio virtual, selecciona tu correo y continúa con tu caso, la animación de Entities y las fichas del final.

Clona la misma base común

Clonar es descargar una copia del proyecto desde GitHub. Node.js permite ejecutar las herramientas de JavaScript que usan NestJS y Expo.

Comprueba que Node.js funciona. Después descarga el proyecto y crea tus archivos de configuración a partir de las plantillas:

node --version
git clone https://github.com/albertohdezakkari/typeorm-base.git
cd typeorm-base
ls -la backend

node --version muestra la versión de Node.js. git clone URL descarga la base común de GitHub y cd typeorm-base entra en la carpeta recién creada. ls -la backend lista los archivos de backend, también los ocultos (los que empiezan por punto). Si ya tienes esa carpeta, no vuelvas a clonarla: entra en ella. La configuración de conexión viene preparada en el proyecto; no copies ni crees archivos .env durante la clase.

Archivos ocultos en Git Bash: los nombres que empiezan por punto no aparecen con ls. Ejecuta ls -la backend para ver .env.example, incluido en el repositorio. El archivo .env está excluido de Git; los comandos del backend cargan directamente .env.example, por lo que no es necesario crear otro archivo.
Archivos de configuración ya preparados: backend/.env.example contiene los valores del aula y los comandos del backend ya lo cargan. AppModule ya conecta TypeOrmModule.forRoot() con esas variables. En la clase solo revisamos host localhost, puerto 5432, usuario postgres, contraseña del aula 123456 y base repaso-typescript. El archivo .env local está ignorado por Git; el alumnado no necesita generarlo.

localhost significa “este mismo equipo”. En un móvil apunta al móvil, no al ordenador del aula. Para usar el backend desde el móvil, ambos deben estar en la misma red y el frontend debe indicar la IP del ordenador.

Inicia PostgreSQL y comprueba la base

PostgreSQL es el programa que guarda los datos. Debe estar iniciado antes de conectar la aplicación. Git Bash es la ventana de comandos que usaremos en Windows.

  1. Inicia el servicio PostgreSQL desde Servicios de Windows.
  2. Abre Git Bash y conecta como postgres. En clase usamos contraseña 123456, host localhost (este ordenador) y puerto 5432. La plantilla del backend ya tiene esos valores.
  3. Si aún no existe la base, créala una sola vez. Si ya existe, salta el comando de creación.

Primero, desde Git Bash, abre psql, la consola para hablar con PostgreSQL. En este comando, -h localhost conecta con este ordenador; -p 5432 usa el puerto de PostgreSQL; -U postgres entra con el usuario postgres; -d postgres abre la base administrativa llamada postgres; y -W hace que pida la contraseña. Al escribirla no verás caracteres: es normal.

psql -h localhost -p 5432 -U postgres -d postgres -W

Cuando aparezca el indicador de psql, ya no estás escribiendo comandos de Git Bash: escribe este SQL para crear la base de práctica:

CREATE DATABASE "repaso-typescript";

El punto y coma indica que la instrucción SQL terminó. Después escribe \q para salir de psql y volver a Git Bash. Si la base ya existe, no repitas CREATE DATABASE.

Comprueba la conexión a la base. SELECT current_database() pregunta a PostgreSQL qué base está abierta; esperamos repaso-typescript.

En esta variante, -d repaso-typescript abre directamente la base de práctica y -c ejecuta el SQL que va entre comillas; al terminar, psql vuelve a Git Bash.

psql -h localhost -p 5432 -U postgres -d repaso-typescript -W -c "SELECT current_database();"

La contraseña se establece también en PostgreSQL al instalarlo. Escribirla en .env no cambia la contraseña del servidor.

Instala, compila y arranca NestJS

Backend es la parte que recibe peticiones y consulta la base. NestJS es la herramienta con que está construido.

Haz la instalación con Internet. package-lock.json guarda las versiones exactas de las librerías para que todos instalemos las mismas.

npm ci instala las versiones exactas fijadas en package-lock.json; si ya existe node_modules, lo reemplaza. Así todos parten de las mismas dependencias y el archivo de versiones no cambia. --no-audit evita que npm envíe una solicitud adicional con el informe de auditoría durante la instalación; no comprueba ni corrige vulnerabilidades. --no-fund solo oculta un aviso informativo de financiación; no hace falta para instalar y por eso no lo añadimos al comando. npm run build compila el backend y npm run start:dev lo inicia en modo desarrollo.

cd backend
npm ci --no-audit
npm run build
npm run start:dev

Deja abierta esa terminal: el servidor debe seguir funcionando. Abre otra Git Bash desde la carpeta principal del proyecto. API es la puerta para pedir datos al backend. curl envía una petición desde la terminal para comprobar que responde:

curl http://localhost:3000/salud

La respuesta debe indicar estado: ok y base: repaso-typescript. Si no conecta, revisa que PostgreSQL esté iniciado y que su usuario y contraseña coincidan con los valores ya preparados en backend/.env.example. No modifiques el AppModule: la conexión TypeORM ya forma parte de la base común.

También puedes ver el backend como una página: abre http://localhost:3000/salud/vista. Debe aparecer “Backend conectado” y el nombre de la base. Esa página la genera NestJS y solo aparece si el backend ha podido consultar PostgreSQL.

Instala y abre Expo Web

Frontend es la pantalla que usa la persona. Expo permite ejecutar la aplicación React Native en el navegador durante esta práctica.

Con Internet, instala las librerías del frontend; usa npm ci con las mismas opciones explicadas en la pestaña Backend. Mantén abierta la terminal del backend en paralelo:

cd frontend
npm ci --no-audit
npm run web

npm run web abre la pantalla en el navegador. Visita la dirección que muestra Expo. Debes ver “¡Hola, mundo!” y “Backend conectado” con el nombre de la base. Esa respuesta confirma el recorrido completo: la pantalla pide información, NestJS la consulta a PostgreSQL y la devuelve a la pantalla.

Para comprobar de nuevo desde otra terminal:

curl http://localhost:3000/salud

Comprueba que el equipo ya puede trabajar sin Internet

Offline quiere decir sin conexión a Internet. La caché de npm es una copia temporal de las librerías descargadas; comprobaremos que están guardadas antes del corte.

  1. Antes del corte, confirma que instalaste y arrancaste backend y frontend.
  2. Con Internet todavía conectado, prueba reinstalar usando solo la caché local de npm:

--offline prohíbe las conexiones a Internet y obliga a npm a usar las librerías ya guardadas en caché. --no-audit evita la solicitud de auditoría. Si falta una librería en la caché, el comando falla: todavía no se puede cortar Internet. --no-fund no se necesita para esta prueba.

cd backend
npm ci --offline --no-audit
cd ../frontend
npm ci --offline --no-audit

Cuando ambas instalaciones acaben sin errores, corta Internet. PostgreSQL debe seguir iniciado y abre una terminal para NestJS y otra para Expo:

En cada terminal, # inicia un comentario para la persona: Bash lo ignora. Desde la carpeta principal, cd backend entra al backend y npm run start:dev lo arranca. En la otra ventana, cd frontend entra al frontend.

En el último comando, npx ejecuta una herramienta instalada en el proyecto; --no-install le prohíbe descargarla si falta; expo start arranca el servidor de Expo; --offline evita que Expo use servicios de Internet; y --web prepara la versión que se ve en el navegador.

# Terminal backend
cd backend
npm run start:dev

# Terminal frontend
cd frontend
npx --no-install expo start --offline --web

Deja Internet desconectado y abre las dos páginas locales: vista del backend y la dirección de Expo que muestra “¡Hola, mundo!”. En otra terminal ejecuta curl http://localhost:3000/salud: debe mostrar repaso-typescript. Así comprobamos visualmente y con una petición que pantalla, backend y base se comunican sin Internet.

npm install puede cambiar las versiones registradas en el archivo de bloqueo; por eso no lo ejecutes ni instales paquetes después del corte. Si falla npm ci --offline, esa máquina no está preparada: reconecta Internet, resuelve la instalación y repite el ensayo.

Guion de clase · primero la base común, después tu espacio

Meta: toda la clase parte de la misma carpeta typeorm-base. Primero dejamos PostgreSQL, backend y frontend funcionando en cada ordenador. Después cada alumno abre el espacio de aula, selecciona su correo institucional y trabaja con el caso que tiene asignado. En esta actividad, «entorno virtual» significa ese espacio web personalizado; no es un entorno virtual de Python.

Usa las pestañas 1–6 para los comandos y las explicaciones completas. En esta pestaña tienes el orden para dirigir la sesión y decidir cuándo avanzar.

0–5 min · Clonar y configurar la base común

Di: «Todos vamos a partir de la misma base. Abrimos Git Bash y clonamos el repositorio una sola vez; después creamos las configuraciones locales». Sigue la pestaña 1 · Clonar y configurar.

Comprobación: pwd confirma la carpeta y ls muestra backend y frontend.

5–13 min · Conectar PostgreSQL

Di: «Primero encendemos el servicio. La aplicación no puede consultar una base de datos que no está arrancada». Sigue la pestaña 1 · PostgreSQL y comprueba la conexión a repaso-typescript.

Comprobación antes de avanzar: psql conecta y SELECT current_database(); devuelve repaso-typescript.

13–27 min · Arrancar el backend

Abre 3 · Backend. Explica que NestJS recibe peticiones y consulta PostgreSQL. Deja su terminal abierta.

Comprobación: npm run build termina sin errores; curl http://localhost:3000/salud responde con el estado correcto y la base esperada. Muestra también http://localhost:3000/salud/vista.

27–38 min · Ver la pantalla

Abre 4 · Frontend y ejecuta Expo Web en otra terminal. Explica que frontend es la pantalla; backend es quien consulta la base. Mantén ambos procesos abiertos.

Comprobación: el navegador muestra «¡Hola, mundo!» y el estado de conexión. Repite el curl para que vean la respuesta del backend.

38–43 min · Ensayo completo

Recorre 6 · Demo visual y pide que cada alumno señale el flujo: pantalla → API NestJS → PostgreSQL → respuesta a la pantalla. Si una parte falla, detén la transición y vuelve a su pestaña de preparación para corregirla.

Regla para avanzar: cada ordenador debe mostrar la pantalla y responder al curl. La instalación offline se ensaya en 5 · Ensayo offline antes de desconectar Internet.

43–50 min · Pasar al espacio personal

Di: «La base que acabamos de arrancar es el punto de partida común. Ahora abrid el enlace del portal de aula, seleccionad vuestro correo institucional y comprobad que aparece vuestro caso asignado. Yo explicaré Cine → Proyección; vosotros seguiréis la misma secuencia con vuestro contexto».

Comprobación: cada alumno identifica sus dos Entities, la cardinalidad 1:N y la carpeta donde empezará. A continuación, abre el espacio virtual del alumnado, elige el correo y entra en la pestaña de construcción de Entities para avanzar el primer paso junto con el profesor.

Antes de terminar: deja backend, frontend y PostgreSQL activos si continuaréis inmediatamente con la práctica. No desconectes Internet hasta confirmar las dependencias en la pestaña de ensayo offline.

Base común de aprendizaje. No contiene casos asignados, examen, censo de alumnado ni soluciones.
